# 统计分析页（Insights）开发优化计划

**日期**：2026-04-15  
**页面**：`/insights` → `InsightsPage.vue`  
**依据**：using-superpowers 流程（上下文 → 方案分阶段 → 实现与验收）；视觉与 `frontend-design` 技能对齐「有意图、可生产、有辨识度」，并与现有用户壳（`UserShellLayout`、`DashboardPage`）保持同一套绿/石色与玻璃拟物语言。

---

## 1. 背景与目标

- **现状**：页面为三段占位 KPI（「—」），缺少层次、氛围与「报表感」，与概览页质感不一致。
- **目标**：
  - **P0**：信息架构清晰、视觉与交互达到可发布水准；占位状态可读、可访问，并为真实数据预留结构。
  - **P1**：对接后端聚合接口（计划数、周完成、进度分布等），替换占位值。
  - **P2**：引入图表库（如 ECharts / Chart.js）与导出/筛选（时间范围、计划类型）。

---

## 2. 设计原则（frontend-design 落地约束）

| 维度 | 方向 |
|------|------|
|调性 | 与产品一致的「清新专业」：主色 `#0a8f4a` / 石色正文，避免通用「白底紫渐变」模板感。 |
| 层次 | 氛围底（柔光 + 轻噪点）+ `dash-panel` 级卡片，与 `DashboardPage` 同源。 |
| 差异化 | 统计分析专属：微型「趋势骨架」、KPI 角标与图例区，一眼区别于概览「工作台」。 |
| 动效 | 卡片级联入场；尊重 `prefers-reduced-motion`。 |
| 字体 | 沿用全站 `font-plan`，不额外引入 Inter/Roboto。 |

---

## 3. 分阶段交付

### 阶段 P0 — 样式与静态结构（当前迭代）

- [x] 页面根布局：`font-plan`、氛围光斑、`dash-home-grain` 同级噪点。
- [x] KPI 三卡：图标区、标题、主指标占位、副文案「数据接入后展示」。
- [x] 次级区块：「指标趋势」占位（CSS 骨架条/伪图表）+ 「数据说明」侧栏。
- [x] 底栏提示：报表 API 与图表组件接入说明（短句，不遮挡主内容）。

### 阶段 P1 — 数据与 API

- [ ] 在 `api-client` 定义 `GET /me/insights`（或等价命名）响应类型：进行中计划数、本周完成任务数、加权平均进度、可选时间序列点。
- [ ] API 层：从 `Plan` / 打卡提交聚合；权限仅本人数据。
- [ ] 前端：`InsightsPage` 拉取、加载态/错误态、`UiErrorToast` 与概览一致。

### 阶段 P2 — 图表与增强

- [ ] 折线/柱状：完成率、打卡次数周趋势。
- [ ] 筛选：年份/计划类型；空状态与权限提示。
- [ ] （可选）CSV 导出、打印友好样式。

---

## 4. 验收标准（P0）

- 路由 `/insights` 在桌面与窄屏下无横向错位；侧栏高亮「统计分析」不变。
- 键盘可达：主要区块具备语义标题（`aria-labelledby`或 `section` + `h2`）。
- 动效在「减少动态效果」系统设置下关闭或降级。
- 与 `DashboardPage` 视觉语言一致，无未使用的重型依赖。

---

## 5. 风险与依赖

- **数据定义**：「本周」「平均进度」的计算口径需在 P1 与 PRD 对齐（自然周 vs 滚动7 天、进度是否含草稿）。
- **性能**：P2 图表需注意大数据年份下的采样或分页。
