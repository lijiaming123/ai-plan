# 计划草稿页内容互换设计（跨日期交换内容，不改日期归属）

**日期**：2026-04-23  
**范围**：`apps/web-user` 计划创建后草稿页、计划详情页草稿态打卡计划表格，以及相关草稿 schedule 更新 API  
**状态**：待产品确认后进入实现（建议再执行 `writing-plans` 拆 Story）

---

## 1. 背景与目标

当前 AI 生成计划后，用户在草稿页/草稿态表格中可以：

- 查看 `schedule.slots`
- 编辑某个 `slotKey` 对应的 `content`
- 恢复单个 slot 的默认内容

但当生成结果出现“**日期内容放错位置**”时，用户只能手动复制/粘贴两行内容，效率低且容易出错。

本次目标不是做通用排序系统，而是提供一个**低风险的草稿校正能力**：

> 允许用户在草稿阶段，将两个不同日期（两个 `slotKey`）的**内容文本互换**，但**不改变日期归属、`slotKey`、通知键、打卡键和后续执行链路**。

---

## 2. 现状摘要（代码事实）

| 区域 | 现状 |
|------|------|
| 草稿/执行 schedule 结构 | `schedule.slots` 为数组项，核心字段包含 `slotKey` 与 `content` |
| 单项编辑 | `PlanDetailPage.vue` 中已有 `openScheduleEdit(slotKey, content)` 与 `patchPlanScheduleSlot` |
| 单项恢复 | 已有 `restoreScheduleSlot(slotKey)`，仍基于 `slotKey` |
| 通知中心跳转 | 通知页跳转详情页时通过 `query: { slotKey, openCheckin: "1" }` 定位 |
| 执行与提交通道 | 打卡/申诉/提交记录均以 `slotKey` 为定位键，不是按“内容文本”定位 |

结论：当前系统里 **`slotKey` 是稳定主键**。如果要支持“跨日期交换内容”，最安全的方式是：

- 只交换两个 slot 的 `content`
- 保持两个 slot 的 `slotKey` 原样不动

---

## 3. 问题定义

用户诉求已确认如下：

- 需要支持**跨日期调整**
- 但只交换**内容本身**
- **不交换日期归属**
- **不交换 `slotKey`**

因此，产品定义不是：

- 拖拽重排 schedule 顺序
- 调整 slot 的日期/归属
- 重新生成时间槽主键

而是：

> 在草稿期支持“把 A 日期的计划内容与 B 日期的计划内容互换”。

---

## 4. 可选方案对比

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A（推荐）** | 行级“交换内容”操作：选定当前 slot，再选择目标 slot，确认后交换两者 `content` | 风险最低；用户意图清晰；不影响 `slotKey` 链路 | 只适合双向交换，不适合大规模重排 |
| B | 拖拽两行进行位置交换，但底层仍只交换 `content` | 更直观 | 容易让用户误以为日期也变了；移动端和拖拽反馈复杂 |
| C | 批量调整模式：在专门面板里重分配内容到目标日期 | 适合一次修改多项 | 过重；明显超出当前需求 |

**推荐**：采用 **A**，定义为一个清晰的“草稿校正工具”。

---

## 5. 推荐设计

### 5.1 功能边界

只在 **草稿阶段** 开放。

建议规则：

- `plan.status === "draft"` 时显示入口
- `active / archived` 不显示
- 交换后只变更 `slot.content`
- 不改变：
  - `slot.slotKey`
  - 日期归属
  - 通知定位
  - 打卡记录 / 提交记录 / 申诉记录绑定关系

### 5.2 入口位置

在草稿态表格每一行现有操作区：

- `编辑`
- `恢复`

旁边新增：

- `交换内容`

移动端卡片区也提供同名按钮，保持一致。

### 5.3 交互流程

推荐流程：

1. 用户点击某行的 **交换内容**
2. 打开“交换计划内容”弹窗
3. 弹窗展示：
   - 当前日期（当前 `slotKey`）
   - 当前内容摘要
   - 目标日期选择器
   - 目标内容摘要预览
4. 用户确认后执行交换
5. 成功后：
   - toast：`已交换 D1 与 D3 的计划内容`
   - 当前表格中的两行内容立即更新

### 5.4 弹窗文案建议

标题：

- `交换计划内容`

说明：

- `仅交换内容，不改变日期归属与后续打卡键。`

确认文案：

- `将 D1 与 D3 的计划内容互换`

按钮：

- `取消`
- `确认交换`

---

## 6. 数据与接口建议

### 6.1 数据原则

本次不新增排序字段，不引入“可拖拽顺序”的新模型。

只做最小能力：

- 输入：`slotKeyA`、`slotKeyB`
- 行为：交换两个 slot 的 `content`
- 输出：新的 `schedule`

### 6.2 API 方向

建议新增一个明确的草稿交换接口，而不是复用“单项编辑”接口做两次写入。

候选形式：

- `POST /plans/:id/schedule/slots/swap-content`

请求体示例：

```json
{
  "slotKeyA": "D1",
  "slotKeyB": "D3",
  "version": 2
}
```

服务端行为：

1. 校验两个 `slotKey` 都存在
2. 校验两者不能相同
3. 交换二者 `content`
4. 保持 `slotKey` 不变
5. 返回新的 `schedule`

不建议前端通过“两次 patch 单项 content”来模拟交换，因为：

- 中间失败会留下半成功状态
- 回滚复杂
- 不利于后端保证原子性

---

## 7. 异常与边界处理

### 7.1 基础限制

- 不能选择自己和自己交换
- 目标 slot 不存在时不可提交
- 若当前草稿版本已变化，返回明确错误并提示用户刷新

### 7.2 空内容场景

若某一侧内容为空，仍允许交换，但要明确提示：

- `你将把空内容与 D3 的计划内容互换`

### 7.3 并发与版本

建议沿用现有草稿版本机制（如已有 `version`）：

- 交换请求带上当前草稿版本
- 若版本不一致，返回“草稿已更新，请刷新后重试”

---

## 8. UI 验收标准

### 桌面端

- 草稿表格每行都有 `交换内容` 按钮
- 点击后弹出模态框
- 目标 slot 选择器可看到其它日期
- 确认后两行内容即时互换

### 移动端

- 草稿卡片操作区同样可进入交换流程
- 弹窗内容在窄屏上可读，不出现长文本溢出

### 反馈

- 成功：toast 明确说明交换的是哪两个日期
- 失败：就地错误提示或 toast，避免静默失败

---

## 9. 测试要点

至少覆盖以下场景：

1. `D1` 与 `D2` 正常交换，内容互换成功
2. `slotKey` 不变
3. 同一个 slot 不能和自己交换
4. 目标 slot 不存在时失败
5. 版本冲突时返回明确错误
6. 一侧为空内容时仍可交换
7. 移动端入口存在
8. 通知中心跳转到 `slotKey` 后仍能定位正确日期

| 阶段 | 内容 | 风险 |
|------|------|------|
| Phase 1 | 草稿态表格/卡片增加 `交换内容` 入口与弹窗 UI | 低 |
| Phase 2 | 新增后端原子交换接口，前端接入 | 中 |

---

## 11. 最终推荐结论

建议将本功能定义为：

> **草稿期计划内容互换（slot content swap）**

它解决的是 AI 生成结果中“日期内容错位”的修正问题，而不是计划排序系统。

本期建议明确不做：

- 拖拽重排
- 修改日期归属
- 修改 `slotKey`
- 执行态开放交换

这样可以用最小成本，解决真实用户问题，同时不破坏现有通知、打卡和提交模型。
