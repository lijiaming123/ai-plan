# 企业内部 RAG 知识库 PRD 评估

**日期**：2026-05-26  
**对照文档**：`general-rag/prd.md`  
**评估方法**：superpowers（目标/范围/架构/可落地性/与现状差距）

---

## 1. 结论（是否合理）

**总体结论：合理，可作为中长期产品蓝图；必须以分阶段（MVP → 增强 → 企业级）落地，不可一次性全量实现。**

| 维度 | 评价 | 说明 |
|------|------|------|
| 定位与目标 | ✅ 合理 | 私有化、可溯源、权限可控，符合内网 RAG 场景 |
| 四层架构 | ✅ 合理 | 与现有 `rag_python` / `rag_node` / `rag_frontend` 分层一致 |
| 知识分类体系 | ✅ 合理 | 六大类 + 四级目录是成熟做法，需映射到「集合 + 元数据」 |
| 10 项元数据 | ✅ 合理 | 应作为入库标准字段，可先必填核心项、其余渐进 |
| 权限三维 | ⚠️ 部分合理 | 「角色+部门+保密等级」正确；当前仅有集合 RBAC，部门/密级需二期 |
| 混合检索 + Rerank | ⚠️ 合理但重 | 需 Elasticsearch/关键词索引或 Chroma hybrid，单迭代不做 |
| 审核流 / 投稿 | ✅ 合理 | 工作流重，适合 Phase 3 |
| 多端（企微/钉钉） | ✅ 合理 | Phase 4，与 Web 共用 BFF API |
| UI：首页三栏 | ✅ 合理 | 与 PRD 6.2.1 一致，适合作为 Web 主入口重构目标 |

---

## 2. 与当前项目差距（Gap）

| PRD 能力 | 当前状态 | Phase 1 目标 |
|----------|----------|--------------|
| 智能问答 + 溯源 | ✅ 已有 | 统一无知识回复文案、展示元数据 |
| 知识库集合 | ✅ `collections` | 增加 `category`（六大类） |
| 文档入库 | ✅ txt/md | 增加标准元数据 Form 字段 |
| 权限 RBAC | ✅ viewer/editor/owner | 保持，密级过滤二期 |
| 首页三栏 | ❌ 列表+分路由 | **工作台**左分类/中问答/右动态 |
| 10 项元数据 | ❌ 仅 filename | chunk metadata 写入核心字段 |
| 脱敏/审核/统计 | ❌ | 计划书登记，不本迭代实现 |
| 混合检索 | ❌ 纯向量 | 计划书登记 |

---

## 3. 分阶段建议

- **Phase 1（本次重构）**：领域模型（分类+元数据）、工作台 UI、防幻觉文案、Node 转发元数据
- **Phase 2**：保密等级过滤、多轮对话、答案评价
- **Phase 3**：投稿审核流、版本回滚、运营统计
- **Phase 4**：混合检索/Rerank、企微内嵌、OCR 多格式

---

## 4. 风险与约束

- PRD 中「100% 无幻觉」需通过 **检索阈值 + 固定拒答话术 + 审计** 组合逼近，不能仅靠 Prompt。
- 大厂级全功能预估 **> 8 人周**，本次仅交付可运行的 Phase 1 对齐。
